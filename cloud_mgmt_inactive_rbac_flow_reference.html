Inactive RBAC Cleanup Flow Reference

End-to-end processing flow for Azure inactive/deleted user RBAC cleanup in the ABI Cloud Management request handler repo.

Request prep file abi_cloud_mgmt/Catalog/Azure/InactiveRbac/InactiveRbac.py
Execution file Catalog/Azure/InactiveRbac/InactiveRbac.py
Main activity table tblActivityAzInactiveRbac

Purpose

The Inactive RBAC flow removes Azure role assignments for inactive or deleted users. The repo is split into two major parts:

  • abi_cloud_mgmt prepares ServiceNow data, inserts event/activity rows, and publishes work to Service Bus.
  • The root Durable Functions app receives handler messages, runs the Azure action, and updates activity status through status monitoring.
Current repo note: Some INACTIVERBAC switch cases and activity registrations are commented for testing. The flow below describes the intended full path once those are enabled.

High-Level Flow

Request payload
  -> RequestReceiver
  -> AzInactiveRbac.snow_data()
  -> ServiceNow item
  -> tblEventMaster
  -> NewActivity / AzPayloadDeserializer
  -> AzInactiveRbac.activity_data()
  -> tblActivityAzInactiveRbac + tblEventPendingActivity
  -> Processor publishes request_handler message
  -> Durable orchestration
  -> root InactiveRbac.delete_inactive_users_roles()
  -> StatusMonitor updates activity row
  -> Processor detects all rows done
  -> tblEventCompletedActivity
  -> CompletedActivity finalizes ServiceNow and tblEventMaster

Detailed Step Flow

  1. Request enters the receiver The Azure Function receiver accepts the request or Service Bus message and passes the payload to RequestReceiver.request_initilize(data).
    File: abi_cloud_mgmt/function_app.py
  2. RequestReceiver routes by cloud For payload.cloud == "Azure", it calls AzActivityNames().get_activity_type_data(data).
    File: abi_cloud_mgmt/RequestReceiver/RequestReceiver.py
  3. Azure activity mapper prepares ServiceNow payload For ActivityName == "INACTIVERBAC", the intended call is AzInactiveRbac().snow_data(data). This builds description, short_description, business_service, and ServiceNow catalog variables.
    File: abi_cloud_mgmt/RequestReceiver/ActivityNames/AzActivityNames.py
  4. ServiceNow request/change/incident is created Depending on ActivityType, the request is sent through SnowRequest, SnowChangeRequest, or incident handling. Then the event is inserted into tblEventMaster.
    File: abi_cloud_mgmt/RequestReceiver/RequestReceiver.py
  5. NewActivity scans approved or queued work The timer processor calls NewActivity().check_db_for_new_activity(), which reads tblEventMaster through get_new_activity().
    Files: abi_cloud_mgmt/RequestProcessor/RequestProcessor.py, abi_cloud_mgmt/RequestProcessor/ActivityType/NewActivity.py
  6. Payload is deserialized into activity rows For ActivityName == "INACTIVERBAC", the intended call is self.objinactiverbac.activity_data(dataset).
    File: abi_cloud_mgmt/RequestProcessor/PayloadDeserializer/AzPayloadDeserializer.py
  7. AzInactiveRbac.activity_data inserts work items It reads dataset.Payload, loops through inactive_user_details, expands role assignments and scopes, determines scope type, resolves zone, and merges rows into tblActivityAzInactiveRbac. It also inserts a row into tblEventPendingActivity.
    File: abi_cloud_mgmt/Catalog/Azure/InactiveRbac/InactiveRbac.py
  8. PendingActivity picks up pending work PendingActivity.get_next_pending_activity() reads tblEventPendingActivity and routes Azure work to AzProcessor.initialize(dataset).
    File: abi_cloud_mgmt/RequestProcessor/ActivityType/PendingActivity.py
  9. AzProcessor resolves the activity table For INACTIVERBAC, get_table_and_topic_names() returns tblActivityAzInactiveRbac.
    File: abi_cloud_mgmt/RequestProcessor/Processor/AzProcessor.py
  10. Processor publishes Service Bus messages Processor.queue_processor() reads rows from tblActivityAzInactiveRbac where status is In-Progress or Retry. Each row is converted into a message and sent to the request_handler topic.
    File: abi_cloud_mgmt/RequestProcessor/Processor/Processor.py
  11. Root request_handler starts Durable orchestration The root Azure Function receives the Service Bus message from request_handler, checks if the orchestration instance already exists, and starts orchestrate_activity.
    File: function_app.py
  12. Orchestrator calls the activity For normal activities, OrchestrationClassifier calls context.call_activity(str(data["ActivityName"]).lower(), data). For INACTIVERBAC, this becomes activity name inactiverbac.
    File: Orchestration/OrchestrationClassifier.py
  13. Activity blueprint invokes the classifier method az_activity_blueprint.py dynamically maps activity name inactiverbac to AzActivityClassifier.inactiverbac_activity().
    File: az_activity_blueprint.py
  14. Azure RBAC deletion runs AzActivityClassifier.inactiverbac_activity() calls InactiveRbac(self.data).delete_inactive_users_roles(). That method deletes the role assignment by ID, handles last-admin assignment errors, handles scope locks, removes locks if needed, retries, and restores locks.
    File: Catalog/Azure/InactiveRbac/InactiveRbac.py
  15. Durable status becomes Completed or Failed The deletion method itself does not update SQL on success. If it returns normally, Durable marks the activity/orchestration as completed. If it raises, the blueprint logs the error into tblActivityInfo and Durable marks it failed.
  16. StatusMonitor updates activity table The root timer status_monitor runs every five minutes. It checks Durable orchestration status and updates the matching row in tblActivityAzInactiveRbac.
    File: StatusMonitor/StatusMonitor.py
  17. Processor detects completion On a later processing cycle, if no rows remain in In-Progress or Retry, Processor.queue_processor() counts success and failure rows, then inserts a summary into tblEventCompletedActivity.
  18. CompletedActivity finalizes the event CompletedActivity.cleanup_completed_activity() updates ServiceNow, updates tblEventMaster, deletes tracking rows from tblEventPendingActivity and tblEventCompletedActivity, and sends notification.
    File: abi_cloud_mgmt/RequestProcessor/ActivityType/CompletedActivity.py

Important Methods

Method File Responsibility
AzInactiveRbac.snow_data(data) abi_cloud_mgmt/Catalog/Azure/InactiveRbac/InactiveRbac.py Builds ServiceNow description, short description, business service, and catalog variables.
AzInactiveRbac.activity_data(dataset) abi_cloud_mgmt/Catalog/Azure/InactiveRbac/InactiveRbac.py Expands payload into rows in tblActivityAzInactiveRbac and marks event pending.
Processor.queue_processor(tblname, dataset) abi_cloud_mgmt/RequestProcessor/Processor/Processor.py Publishes individual activity rows to Service Bus topic request_handler.
InactiveRbac.delete_inactive_users_roles() Catalog/Azure/InactiveRbac/InactiveRbac.py Deletes Azure role assignment and handles special Azure errors.
StatusMonitor.update_status() StatusMonitor/StatusMonitor.py Polls Durable status and updates activity table row status.
CompletedActivity.cleanup_completed_activity() abi_cloud_mgmt/RequestProcessor/ActivityType/CompletedActivity.py Finalizes ServiceNow and master event state after all rows are done.

Status Transitions

Stage Table Status / Meaning
Request created tblEventMaster Pending Approval or Queued
Approved / ready for processing tblEventMaster In-Progress
Activity rows created tblActivityAzInactiveRbac In-Progress
Work pending tblEventPendingActivity Contains event/activity with next retry time.
Durable completed tblActivityAzInactiveRbac Success, comment Implemented Successfully
Durable failed tblActivityAzInactiveRbac Retry or Failed, depending on runtime status.
All rows done tblEventCompletedActivity Success, Failed, or partial failure summary.
Final cleanup tblEventMaster Final status such as Completed, Remediated, or failure state.
