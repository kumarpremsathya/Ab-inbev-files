Git Stash, Pull --Rebase & Stash Pop

Beginner-friendly reference for resolving a rejected Git push

Your Situation

Your local branch has committed changes, the remote feature1 branch has newer commits, and you also have unstaged changes.

Goal: Safely protect your unfinished work, update your branch with the remote changes, push your committed work, and then restore the unfinished work.

1. git stash

Purpose: Temporarily saves your uncommitted changes and makes your working directory clean.
git stash

Example

Committed: file1.py Uncommitted: file2.py (changed but not committed)

After running git stash, the file2.py changes are stored temporarily in Git and your working directory becomes clean.

Easy memory: “Put my unfinished work safely in a temporary box.”

2. git pull --rebase origin feature1

Purpose: Gets the latest commits from the remote Azure DevOps feature1 branch and places your local commits on top of those remote commits.
git pull --rebase origin feature1

Think of it as two steps:

1Pull
Download the latest remote commits.
2Rebase
Reapply your local commits after the latest remote commits.

Example before rebase

Remote: A -- B -- C Local: A -- B -- D

After rebase

A -- B -- C -- D
Easy memory: “First get the latest remote code, then place my commits on top.”

Why? This is useful when your push is rejected with rejected (fetch first) because the remote branch contains commits you do not yet have locally.

3. git stash pop

Purpose: Restores the uncommitted changes that you previously saved with git stash.
git stash pop
Easy memory: “Take my unfinished work back out of the temporary box.”

Example

Before stash: Committed: file1.py Uncommitted: file2.py changes After git stash: Working directory: clean Stash: file2.py changes After git pull --rebase: Branch updated with latest remote commits After git stash pop: file2.py changes are restored as uncommitted changes

4. Your Exact Workflow

git status
git stash
git pull --rebase origin feature1
git push origin feature1
git stash pop
CommandWhat it does
git statusShows whether you have uncommitted or staged changes.
git stashTemporarily protects your current uncommitted changes.
git pull --rebase origin feature1Brings the latest remote changes and reapplies your local commits on top.
git push origin feature1Pushes your now-up-to-date local branch to Azure DevOps.
git stash popRestores the changes you temporarily stashed.

5. Important Point After stash pop

The changes restored by git stash pop are uncommitted again.

If you want to save them permanently in Git and push them, review and commit them:

git status
git add .
git commit -m "your message"
git push origin feature1

6. What NOT to Do

Do not use git push --force just to solve a fetch-first rejection unless you are certain the remote commits should be overwritten. A force push can remove other people's commits from the remote branch.
