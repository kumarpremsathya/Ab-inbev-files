Azure Functions Host and CORS Guide

This document explains what the Host section means in local.settings.json, especially this local development setting:

{
  "Host": {
    "CORS": "*"
  }
}

1. What Does Host Mean?

In local.settings.json, Host means the Azure Functions host/runtime settings.

It does not mean:

  • Your computer hostname
  • Your frontend host
  • Your backend Python function code directly

It means the runtime process that starts when you run:

func start
Simple meaning: Host = the Azure Functions runtime around your code.

2. Two-Layer Mental Model

An Azure Function app has two important layers:

Browser / client
   |
   v
Azure Functions Host
   |
   v
Your Python function code

The browser request reaches the Azure Functions Host first. Only after that does the host call your Python function method like test_request_receiver().

3. What The Functions Host Does

The Functions host/runtime is responsible for:

  • Opening http://localhost:7071
  • Registering routes like /api/test_request_receiver
  • Receiving HTTP requests before your Python code runs
  • Handling function keys and auth level
  • Handling CORS
  • Loading HTTP triggers, timer triggers, and Service Bus triggers
  • Deciding which function method to call
So CORS is handled before your Python line data = req.get_json() runs.

4. Why CORS Is Needed Here

Your HTML test page runs from Live Server:

http://127.0.0.1:5500

Your Azure Function runs from the Functions host:

http://localhost:7071

Even though both are on your laptop, the browser sees them as different origins.

127.0.0.1:5500  !=  localhost:7071

The browser compares protocol, host, and port:

PartFrontendBackend FunctionSame?
ProtocolhttphttpYes
Host127.0.0.1localhostNo
Port55007071No
Because host/port differ, the browser applies CORS rules.

5. What Happens During CORS Preflight

Before the real POST request, the browser sends an automatic OPTIONS request:

OPTIONS /api/test_request_receiver
Origin: http://127.0.0.1:5500
Access-Control-Request-Method: POST
Access-Control-Request-Headers: content-type

This is called a CORS preflight.

The browser is asking the backend:

Is http://127.0.0.1:5500 allowed to send a POST request with JSON content to you?

When you add this setting:

"Host": {
  "CORS": "*"
}

The Functions host can respond with CORS headers, similar to:

Access-Control-Allow-Origin: *
Access-Control-Allow-Methods: GET,POST,OPTIONS
Access-Control-Allow-Headers: Content-Type

Then the browser allows the real POST request.

6. Why The Earlier Error Happened

You saw an error like:

ValueError: HTTP request does not contain valid JSON data

That happened because the function received a request without JSON body, most likely the browser's OPTIONS preflight request.

Your function code was doing:

data = req.get_json()

But the OPTIONS request has no JSON body, so req.get_json() failed.

With Host CORS configured, the Functions host handles preflight before it reaches your Python function.

7. Host vs Values

Values and Host are different sections.

SectionPurposeWho Uses It?
ValuesEnvironment variables for your application codeYour Python code
HostSettings for the Azure Functions runtimeAzure Functions host

Values Example

"Values": {
  "Environment": "Local",
  "DATABASE": "config-mgmt-dev"
}

Your Python code can read these:

os.environ.get("Environment")

Host Example

"Host": {
  "CORS": "*"
}

This is read by the Functions runtime, not normally by your Python code.

Memory shortcut: Values = settings for your code. Host = settings for the runtime around your code.

8. What CORS "*" Means

The value "*" means:

Allow browser requests from any origin.

For local testing, this is usually fine:

"Host": {
  "CORS": "*"
}

For production, avoid "*". Use the actual frontend URL instead, for example:

"Host": {
  "CORS": "https://your-frontend-domain.com"
}
Production should restrict CORS to trusted frontend domains.
