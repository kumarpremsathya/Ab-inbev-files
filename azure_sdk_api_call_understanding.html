Files covered: shared_code/policy_insights_client.py  |  AzPolicyStates/policy_test.py

1. File Structure & Responsibilities

File Job What it does
shared_code/policy_insights_client.py Client Setup Creates and returns a PolicyInsightsClient object (authentication + connection)
AzPolicyStates/policy_test.py Business Logic Fetches policy states from all subscriptions, normalizes data, saves to DB
shared_code/subscriptions_client.py Subscription List Returns list of all enabled Azure subscriptions
shared_code/client_secret_auth.py Authentication Fetches SPN credentials from Key Vault and returns ClientSecretCredential
Design Pattern: Each file has ONE job. This follows the same pattern as authorization_client.py, subscriptions_client.py, and resourcegraph_client.py in the repo.

2. Why policy_insights_client.py was Created Separately

Repo pattern — every SDK client has its own shared_code file:

Shared Code File Wraps This SDK Client
subscriptions_client.py SubscriptionClient
authorization_client.py AuthorizationManagementClient
resourcegraph_client.py ResourceGraphClient
policy_insights_client.py ← NEW PolicyInsightsClient
Extra improvement: policy_insights_client.py uses ClientSecretAuth().client_credential() (1 line) instead of manually calling SpnToken → ClientSecretCredential (3 lines) like older files do. This is the cleaner, correct approach using the abstraction already built in shared_code.

4. Why subscription_id is Passed to PolicyInsightsClient

subscription_id is NOT for authentication. It is used to build the Azure REST API URL.
Parameter Purpose Analogy
credential Authentication — WHO are you? Your ID card / passport
subscription_id Routing — WHERE to send the request? The destination address

API URL that gets constructed internally:

https://management.azure.com
    /subscriptions/{subscription_id}    ← subscription_id used here
    /providers/Microsoft.PolicyInsights
    /policyStates/latest/queryResults

Why SubscriptionClient does NOT need subscription_id:

# SubscriptionClient — LISTS all subscriptions (tenant level)
# URL: GET https://management.azure.com/subscriptions
SubscriptionClient(credentials)   # no subscription_id needed

# PolicyInsightsClient — queries ONE subscription at a time
# URL: POST https://management.azure.com/subscriptions/{sub_id}/...
PolicyInsightsClient(credential, subscription_id)   # subscription_id required

5. Does it Query All Subscriptions? (subscriptions[0] Doubt)

Yes — all subscriptions are queried. subscriptions[0] is only a placeholder to satisfy the SDK constructor. The loop overrides it. 
# Client created with subscriptions[0] as default
client = PolicyInsightsClientFactory().get_policy_client(azenvironment, subscriptions[0])

# Loop iterates ALL subscriptions
for idx, sub_id in enumerate(subscriptions, 1):
    records = client.policy_states.list_query_results_for_subscription(
        policy_states_resource="latest",
        subscription_id=sub_id   # ← explicitly overrides constructor default each time
    )
Constructor call Loop iteration 1 Loop iteration 2 Loop iteration 3
subscriptions[0] (default) sub-AAA (explicit) sub-BBB (explicit) sub-CCC (explicit)

6. SPN Access — Why There's No Permission Issue

_get_subscriptions() — uses "az-public-spn-reader" SPN → returns only subscriptions this SPN can access
↓
PolicyInsightsClientFactory().get_policy_client() — uses same "az-public-spn-reader" SPN
↓
Loop — queries each subscription the SPN already proved it can access
Same SPN is used throughout. If the SPN can list a subscription, it can query its policy states. Zero permission risk.

7. Complete Flow — End to End

── get_policy_states() called ──────────────────────────────────────
  calls policy_states_api("AzurePublicCloud")
  calls policy_states_api("AzureChinaCloud")
  combines results → saves to DB

── policy_states_api(azenvironment) ────────────────────────────────
  Step 1: _get_subscriptions()
          └── SubscriptionsClient().get_subscription_client(azenvironment)
          └── Lists all ENABLED subscriptions using "az-public-spn-reader"
          └── Returns: ["sub-001", "sub-002", "sub-003", ...]

  Step 2: PolicyInsightsClientFactory().get_policy_client(azenvironment, subscriptions[0])
          └── Picks spn_secret_name based on environment
          └── ClientSecretAuth().client_credential(spn_secret_name)
              └── Fetches SPN details from Key Vault
              └── Returns ClientSecretCredential
          └── Returns PolicyInsightsClient(credential, subscriptions[0])
              └── No API call yet — just object prepared

  Step 3: Loop over all subscriptions
          └── For each sub_id:
              └── client.policy_states.list_query_results_for_subscription(
                      policy_states_resource="latest",
                      subscription_id=sub_id    ← actual API call here
                  )
              └── Retry 3 times on failure (exponential backoff)
              └── Collect all records

  Step 4: _normalize_results()
          └── Converts snake_case SDK response → camelCase schema
          └── Returns list of normalized dicts

8. Breakdown of the Actual API Call Line

records = client.policy_states.list_query_results_for_subscription(
    policy_states_resource="latest",
    subscription_id=sub_id
)

What each part does:

Part What it is
client The PolicyInsightsClient object created in policy_insights_client.py
.policy_states The module inside the SDK that handles policy state operations
.list_query_results_for_subscription(...) The actual API method that makes the HTTP call
policy_states_resource="latest" Tells Azure: give me the latest policy states (not historical)
subscription_id=sub_id The subscription to query — changes in each loop iteration
