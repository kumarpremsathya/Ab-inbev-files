What is a Service Principal?

A Service Principal (SPN) is an identity in Azure Active Directory (Entra ID) that an application uses to authenticate and access Azure resources — essentially an "app identity" (as opposed to a user identity). It has a client_id, client_secret, and tenant_id.

How it's used in this project

This project uses SPNs in two ways:

1. As authentication credentials (to run the app itself)

The app authenticates to Azure APIs using SPN credentials stored in Azure Key Vault:

FlowFiles
Fetch secret from Key Vaultshared_code/akv_secrets.py
Parse SPN JSON (client_id, secret, tenant)shared_code/spn_token.py
Create ClientSecretCredentialshared_code/client_secret_auth.py
Use credential to call Microsoft Graph APIshared_code/graphservice_client.py
Use credential for Azure RBAC/Managementshared_code/authorization_client.py

The chain works like this:

Azure Key Vault secret (e.g. "az-public-spn-reader") → JSON: {"client_id": "...", "secret": "...", "tenant": "..."} → ClientSecretCredential(client_id, secret, tenant) → Authenticated API client (Graph, ARM, etc.)

Key Vault secret names used:

  • az-public-spn-reader — for Azure Public Cloud Graph API
  • az-china-spn-reader — for Azure China Cloud Graph API
  • az-public-spn-cloudbolt — for Azure authorization/RBAC operations

2. As data being extracted (the app inventories SPNs)

The app also extracts information about all SPNs in the tenant for IAM governance:

PurposeFile
Extract all app registrations/SPNs (owners, keys, secrets, permissions)AzSPNs/spns.py
Extract SPN sign-in activity logsAzIdentityGovernance/spn_signin_logs.py
Notify SPN owners about expiring secretsNotifySPNOwners/notify_spn_owners.py

Where to check / key locations

  • To see how authentication works: Start at shared_code/spn_token.py → it fetches the SPN secret from Key Vault and returns a dict with client_id, secret, tenant.
  • To see which SPNs are configured: Check Key Vault secrets referenced in shared_code/graphservice_client.py and shared_code/authorization_client.py.
  • To see SPN data extraction logic: Look at AzSPNs/spns.py — it pulls app registrations from Microsoft Graph including owners, key credentials, password credentials, permissions, etc.
  • Runtime config: The Key Vault URI comes from the environment variable KEYVAULT_URI (set in local.settings.json for local dev).

Summary

In short: this Azure Function app uses a service principal to authenticate itself, and extracts data about all service principals in the organization for IAM reporting and governance (expiring secrets notifications, sign-in activity tracking, etc.).

Q: az-public-spn-reader — so this Key Vault secret name is one service principal, correct?

Yes, correct. az-public-spn-reader is the name of a single secret stored in Azure Key Vault. That secret contains a JSON string with the credentials of one service principal:

{
  "client_id": "...",
  "secret": "...",
  "tenant": "..."
}

You can see this in shared_code/spn_token.py — it fetches the secret by name and parses the JSON:

def get_spn_token(self, secret_name):
    secrets_obj = AkvSecrets(os.environ["KEYVAULT_URI"], secret_name)
    spn_token = secrets_obj.get_tokens()
    spn_token = json.loads(spn_token.value)  # → {"client_id": "...", "secret": "...", "tenant": "..."}
    return spn_token

So az-public-spn-reader = 1 Key Vault secret = 1 service principal (an app registration in Azure AD with Reader permissions on the Azure Public Cloud tenant).

Your current file AzSQLServers/sql_servers.py uses it indirectly via ResourceGraph().get_resorce_graph(azenvironment), which internally calls SpnToken().get_spn_token("az-public-spn-reader") for the AzurePublicCloud environment (see shared_code/resourcegraph_client.py).

Q: So this service principal az-public-spn-reader created with {"client_id": "...", "secret": "...", "tenant": "..."} in Azure AD with Reader permissions on the Azure Public Cloud tenant and stored in Key Vault, correct. So we can call this Key Vault secret name as service principal.

Yes, exactly. To summarize:

  1. In Azure AD (Entra ID): An App Registration is created, which generates a client_id and tenant_id. A client secret is then created for it. This app is granted Reader permissions on the tenant's resources.
  2. In Azure Key Vault: The credentials are stored as a single secret named az-public-spn-reader, with the JSON value: 
    {
  "client_id": "...",
  "secret": "...",
  "tenant": "..."
}
  3. In the code: The secret name "az-public-spn-reader" is used to fetch and refer to that service principal.

So yes — in the context of this codebase, the Key Vault secret name (e.g. az-public-spn-reader) is effectively used as the identifier/alias for the service principal. When someone in this project says "the az-public-spn-reader service principal," they mean the Azure AD app registration whose credentials are stored under that Key Vault secret name.

The naming convention in this project makes it clear:

  • az-public → Azure Public Cloud
  • spn → Service Principal
  • reader / cloudbolt / saviynt-xtractor → the role or purpose of that SPN
