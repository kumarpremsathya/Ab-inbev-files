Detailed Step-by-Step Breakdown

1
USER — Frontend
Submits the exemption request
  • Selects Zone → Subscription → Resource Group
  • Picks non-compliant policy assignments from the multi-select grid
  • Sets Exemption Type: Permanent or Temporary
  • Sets number of days (max 60) for temporary exemptions
  • Fills in Justification and Business Impact
  • Agrees to terms and clicks Submit
2
abi_cloud_mgmt › RequestReceiver
HTTP trigger — SNOW ticket creation
  • Receives the HTTP POST request from the frontend
  • Calls AzActivityNames.get_activity_type_data()
  • Routes to AzPolicyExemption.snow_data()
  • Builds SNOW description listing all resources
  • Builds short_description with requestor + subscription
  • Creates SNOW Request ticket (RITM) via SNOWClient
  • Publishes message to Service Bus → request_receiver topic
3
abi_cloud_mgmt › RequestReceiver
Service Bus trigger — master record insert
  • Service Bus trigger receives the message
  • Inserts master record into tblEventMaster
  • Status set to 'Pending Approval'
  • Awaits SNOW approval from zone approver
4
abi_cloud_mgmt › RequestProcessor
Timer (every 4 min) — NewActivity check
  • NewActivity.check_db_for_new_activity() reads tblEventMaster
  • Polls SNOW — awaits request_approved / state=8
  • On approval, calls AzPayloadDeserializer → AzPolicyExemption.activity_data()
  • Loops through each resource in the payload
  • Inserts one row per resource into tblActivityAzPolicyExemption
  • EventId = foreign key linking all rows to the master event
  • Each row gets its own ActivityId
  • Inserts into tblEventPendingActivity
5
abi_cloud_mgmt › RequestProcessor
Timer — PendingActivity publishes to handler
  • PendingActivity.get_next_pending_activity() reads tblEventPendingActivity
  • AzProcessor fetches all rows from tblActivityAzPolicyExemption for this EventId
  • Publishes each resource row as a separate Service Bus message
  • Topic: request_handler
  • Message key = unique hash per resource row
6
abi-mc-az-requesthandler
Service Bus trigger — Durable Function
  • Service Bus trigger receives each message (one per resource)
  • Starts Durable Function orchestration — instance ID = ActivityId
  • OrchestratorClassifier routes to activity: policyexemption
  • Calls AzActivityClassifier.policyexemption_activity()
  • Calls AzPolicyExemption.apply_exemption()
  • Calls Azure Policy SDK: policy_exemptions.create_or_update()
  • Exemption created in Azure at resource scope ✅
  • Category: Waiver (permanent) or Mitigated (temporary)
7
abi-mc-az-requesthandler › StatusMonitor
Timer (every 5 min) — status update
  • Polls Durable Function orchestration status via get_status_by()
  • Matches orchestration instance by EventId + ActivityName
  • If Completed → updates tblActivityAzPolicyExemption row to Success
  • If Failed → updates to Retry or Failed
  • Retry logic re-queues via RetryAttemptedAt timestamp
8
abi_cloud_mgmt › RequestProcessor
CompletedActivity — close SNOW + master
  • CompletedActivity detects all resource rows are Success or Failed
  • If all Success → tblEventMaster Status = 'Completed'
  • If any Failed → Status = 'Closed Incomplete'
  • Calls SNOWClient to close RITM:
  • Success → closed_complete
  • Failure → closed_incomplete
9
abi_multicloudsync
Timer (independent) — Azure snapshot sync
  • Runs on its own schedule — independent of the request flow
  • Queries Azure Resource Graph for ALL existing policy exemptions
  • Covers both AzurePublicCloud and AzureChinaCloud
  • Extracts: id, name, exemptionCategory, policyAssignmentId, expiresOn, scopeType, etc.
  • Stores full JSON snapshot into tblAzPolicyExemptions
  • The exemption created in Step 6 appears here on the next sync run
  • Used by UI to display existing exemptions inventory

Database Tables Reference

Table Repo Written By Purpose
tblEventMaster abi_cloud_mgmt RequestReceiver (SB Trigger) Master record per event — tracks overall Status, SNOW RITM ID, ActivityName
tblActivityAzPolicyExemption abi_cloud_mgmt AzPayloadDeserializer → AzPolicyExemption.activity_data() One row per resource. EventId = FK to master. Tracks per-resource Status (In-Progress → Success/Failed)
tblEventPendingActivity abi_cloud_mgmt DbActivityManager.insert_activity_pending() Queue for pending activities awaiting handler processing. Drives retry logic via RetryAttemptedAt
tblEventCompletedActivity abi_cloud_mgmt DbActivityManager.insert_activity_completed() Records completed activities (Success/Failed) — triggers master record closure
tblAzPolicyExemptions abi_multicloudsync AzPolicyExemptionsXtractor.get_policy_exemptions() Snapshot of ALL existing exemptions in Azure (Public + China). Used for reporting and UI display
