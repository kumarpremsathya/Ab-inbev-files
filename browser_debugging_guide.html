Browser Debugging Guide — Frontend to Backend

Reference for debugging HTTP requests from HTML frontend to Azure Function backend.

1. HTTP Methods

MethodPurposeHas Body?Used When
GETFetch dataNoLoad a page, read resources
POSTSend data to create/triggerYesSubmit a form, trigger a function
PUTUpdate existing resourceYesEdit/update data
DELETEDelete a resourceNoRemove data
Our HTML uses POST because we are submitting a new Policy Exemption request.

2. Request Body / Payload

The body is the data sent with a POST request.

In HTML (JavaScript fetch)

body: JSON.stringify(payload)   // converts JS object → JSON string

In Python test script (requests module)

response = requests.post(url, json=payload)  # auto-converts dict → JSON

In Azure Function (receiving side)

data = req.get_json()   # converts JSON string back → Python dict
Both HTML and Python test script do the same thing. The function cannot tell the difference.

3. Headers

Metadata sent with every request. Most important for JSON APIs:

headers: { "Content-Type": "application/json" }

This tells the server: "my body is JSON, not a form or plain text".
Without this header, req.get_json() can fail.

4. Full API Call Flow

Browser (port 5500)                    Azure Function (port 7071)
  |                                              |
  |--- OPTIONS (CORS preflight) --------------->|   ← browser does this automatically
  |<-- 200 + CORS headers ---------------------|
  |                                              |
  |--- POST /api/test_request_receiver -------->|
  |    Headers: Content-Type: application/json  |
  |    Body: { "ActivityType": "Request", ... } |
  |                                              |
  |<-- 200 "Done. SnowItemId: " --------------|
CORS preflight: Browser sends an OPTIONS request with empty body before the real POST. If the function calls req.get_json() on that OPTIONS request, it crashes. Fix: add "Host": { "CORS": "*" } to local.settings.json and restart func.

6. DevTools (F12) — Network Tab

Press F12 → Network tab → check "Preserve log"

Click Send Request → find test_request_receiver in the list → click it:

Headers sub-tab

Status Code:    200 OK

{
  "ActivityType": "Request",
  "ActivityName": "POLICYEXEMPTION",
  ...

This is exactly what was sent to the function. If this is empty or wrong → bug is in your JS sendRequest() function.

Response sub-tab

Done. SnowItemId:

This is what func.HttpResponse(...) returned from the function.

7. DevTools — Console Tab

If sendRequest() crashes before fetch() runs, the request won't appear in Network at all.

Check Console tab for red errors:

Uncaught TypeError: Cannot read properties of null   ← wrong element id
SyntaxError: ...                                     ← bad JS syntax

CORS error looks like this:

Access to fetch at 'http://localhost:7071/...' from origin 'http://127.0.0.1:5500'
has been blocked by CORS policy: No 'Access-Control-Allow-Origin' header
Fix: Add "Host": { "CORS": "*" } to local.settings.json and restart the function.

Add this to inspect payload before sending:

// Add inside sendRequest() before the fetch() call
console.log("Payload:", JSON.stringify(payload, null, 2));
Check Console tab → you'll see exactly what is about to be sent.
